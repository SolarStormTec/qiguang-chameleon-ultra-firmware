# Security Policy

## Supported versions

Only the latest published firmware release receives security fixes. Older releases should be upgraded before a report is reproduced.

## Reporting a vulnerability

Do not open a public issue containing vulnerability details, private keys, device certificates, or production data. Use GitHub's **Security → Report a vulnerability** form when private vulnerability reporting is enabled. If that option is unavailable, open a public issue asking the maintainers for a private contact method without including technical details.

Include affected versions, hardware model, reproduction steps, impact, and any proposed mitigation. Allow the maintainers a reasonable period to investigate and prepare a coordinated fix before public disclosure.
